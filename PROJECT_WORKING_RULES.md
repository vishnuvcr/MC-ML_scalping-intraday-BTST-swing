# Project Working Rules

This repository follows the research workflow established at project initiation.

1. Keep a finite, phase-based research plan and review governance files before each phase.
2. Keep research phases on separate branches and provide a manual GitHub Actions entry point for each phase.
3. Update phase status and error logs after substantive steps, including failed or negative results.
4. Keep the README current with phase, evidence and links to key project files.
5. Prefer cached, versioned data over repeated downloads when redistribution rights permit.
6. Model brokerage, statutory fees, spread, slippage and relevant financing costs explicitly.
7. Use reproducible Python/Rust research code, recorded seeds, data hashes and versioned experiment specifications.
8. End the study with a structured manuscript, statistical appendices, tables/charts, limitations and future research.
9. Stop at the predefined research phases unless a documented protocol change is required.

Research conclusions must be evidence-based and may be null or negative.
